# Contributing to nxdlang.org

Thank you for your interest in contributing to NXD.

This repository contains the source code and content for the official NXD website. Contributions that improve the website or make NXD's documentation clearer and more useful are welcome.
What Belongs in This Repository?

Appropriate contributions include:

    Website bug fixes
    Documentation corrections
    Accessibility improvements
    Responsive and mobile layout improvements
    Performance improvements
    Broken-link fixes
    Improvements to NXD examples and explanations
    Website UI and navigation improvements

Changes to the NXD compiler or language implementation belong in the appropriate NXD compiler repository.

Changes specific to editor integration, the language server, or extensions belong in the repository responsible for those components.
Before Opening an Issue

Please check existing issues and discussions before creating a new one.

For small documentation corrections or straightforward fixes, a pull request may be submitted directly.

For substantial changes to the site's structure, design, or documentation organization, opening an issue or discussion first is encouraged.
Pull Requests

Keep pull requests focused on one logical change whenever practical.

Before submitting a pull request:

    Make sure the project builds successfully.
    Verify that your changes work at common desktop and mobile sizes when applicable.
    Check any documentation examples you modify for accuracy.
    Avoid unrelated formatting or refactoring changes.
    Provide a clear description of what the pull request changes and why.

Pull requests may be revised, discussed, or declined at the maintainers' discretion.
Documentation

NXD documentation should favor clarity and precision.

Code examples should represent valid NXD syntax for the language version being documented. Avoid documenting proposed behavior as though it is already part of the language.

When describing language behavior, distinguish between syntax, semantics, compiler behavior, and implementation details where that distinction matters.
